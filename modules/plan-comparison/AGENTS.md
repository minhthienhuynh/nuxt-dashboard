- `PLAN_COMPARISON_PLANS` (`plan-colors.ts`) là registry duy nhất cho plan id/label/color — đừng tạo map id song song. Thêm plan = thêm key + entry registry + `plans.ts` + `providers.ts`; `EnrichedModelRow` là `Record<PlanKey, PlanFunding>` nên card/chart/tooltip tự chạy theo registry, không sửa từng key.
- **KHÔNG còn cờ `funding`/`credit_is_per_model`** (bỏ 2026-11-10): mọi plan đều là **một pool chung** với allocation per-model, nên row chỉ là "usage value pool fund trên model đó" (`$X usage` trong tooltip, card ghi `Monthly pool` + `Per-model value`). Bằng chứng: CC "one shared pool with a monthly usage on every model"; OpenDesign "credit allocation — shared pool"; Token Harbor "included usage" + Model Boost; OpenCode Go = `Subscription.getLimits().lite` (một counter chung, mỗi request weight `60 ÷ monthly limit`) → pool **$60**, windows $12/$30/$60, cột $15–$100 trong docs chỉ là allocation. Đừng phân loại lại theo giá/credit — sai một chỗ là chart/tooltip lệch nghĩa.
- Chart vẫn vẽ đúng nghĩa pool: bar/dot = **usage value pool fund trên model đó** (allocation), vd OpenDesign pool **$60** ⇒ allocation $15 (4×)…$220 (Eco 0.27×); OpenCode pool **$60** ⇒ $15 (4×)…$100 (0.6×). Legend plain label (không hậu tố), câu giải thích "one shared pool" chỉ nằm 1 lần ở header mỗi chart; tooltip ghi `$X usage`.
- Cửa sổ không công bố = `null` (KHÔNG bịa số; với OpenDesign cửa sổ CÓ công bố trong bảng allowances nên phải lấy từ đó, đừng để `—`): `PlanLimits['5h']/weekly` và `PlanModelEstimateValues.per_5h/per_week` cho phép null; card hiện `—`; `estimates` per-window null thì dot chart vẫn dùng `per_month`.
- **Credit multiplier là bắt buộc để tính đúng OpenDesign** (không dùng thì số requests sai tới 4×): nguồn `https://open-design.ai/model-credits/` → `parseOpenDesignMultipliers()` (bảng "Design Plan models and credit multipliers", tab Go, ưu tiên `data-go-rate`); credits tiêu = usage$ × multiplier ⇒ pool N credits mua `N/multiplier` dollar usage. Bỏ row promo (`… Off-peak promo`, có cửa sổ riêng — quy ước không bake promo). Model không có trong bảng = 1×. `DeepSeek V4.1 Flash Eco` (0.27×, chỉ Go/Plus) KHÔNG có trang model ⇒ không có giá per-token ⇒ chưa vào dataset (muốn thêm phải có key API hoặc user ra lệnh dùng proxy giá V4.1 Flash).
- OpenDesign Go (`go.open-design.ai`, Astro, không Flight): nguồn **credits + cửa sổ** là bảng **"Plan allowances" / `Model credits by plan`** trên trang pricing → `parseOpenDesignAllowances()` (Go: coding $220/tháng, cửa sổ $55/7 ngày và $18/5 giờ; Plus/Pro/Max ghi "No limit window" cho 5 giờ ⇒ null). Cột bảng này được dò theo header, hai cột cửa sổ nằm ngay sau cột `Coding Plan` (header hàng 2 chỉ span 3 cột cuối nên index của nó KHÔNG khớp row dữ liệu). Settings JSON `data-corouter-settings` KHÔNG parse nữa (không có cửa sổ). Catalog: trang `/models/` → `[data-model-panel]` (API id + tier rates) ghép `a.catalog-card` theo slug (vendor + `Go / Plus / Pro / Max`); panel không card = rate card legacy ⇒ bỏ cả pricing lẫn row. Row `od-go` chỉ cho model đã có trong catalog; **budget = baseline suy ra từ chính bảng usage** (`designCreditBaseline`: median của `usage × multiplier` = **$60**), fallback `plans.ts` (4.91/15/60); bảng allowance in "up to $220" chỉ là allocation LỚN NHẤT (Eco) nên cửa sổ $18/5h + $55/7d được rescale ×(60/220) ⇒ $4.91/$15; `sourceUrl` = trang pricing, nguồn rates ghi trong `note`; tier giá `standard`/`extended` chỉ là dữ liệu tham chiếu.
- **OpenDesign KHÔNG công bố basis của bảng "Coding Plan usage"** (requests/7 ngày + monthly usage per model) — đừng gán basis của provider khác vào đây (bài học 2026-11-06: đã ghi nhầm basis 10K in/8K cache/1K out của TokenHarbor). Vì basis riêng + không công bố nên KHÔNG nhập bảng đó vào dataset: estimates vẫn tính trên profile chung của repo (800 in / vendor out / 50K cache) để so được với CC/OC.
- **TokenHarbor Agent Pass (`th-agent`) là plan kiểu LUẬT + payload công khai, không cần API key**: docs (`/docs/billing/subscription`) công bố luật "≤ $0.20/1M input và ≤ $1/1M output, cộng by-name `gpt-5.6-luna` + `mimo-v2.5-pro`"; catalogue (rates, family, context, Intelligence Index của chính vendor) nằm trong Flight payload trang `tokenharbor.ai/models` → `parseTokenHarborCatalogue()` (mỗi tab một array, `speedBuild` là biến thể con của model gốc ⇒ mở rộng thêm 1 entry, thừa hưởng cache/context/family). Membership do crawler TỰ SUY từ luật (`isAgentPassModel`), **không** copy từ bảng nào: bảng so sánh trên `/pricing` chỉ liệt kê 8/12 model (bỏ by-name và vài model rẻ) ⇒ đếm theo trang là thiếu.
- **Model Boost vs promo (TokenHarbor)**: badge `2×` trên widget `Agent Pass · estimated requests` là boost thường → `monthly_credits_usd = pool × boost` ($10 × 2 = $20, đúng câu "up to $20 of usage value"); badge có `title="2x usage during the promo"` là promo, **không** nhân (promo đã nằm trong giá niêm yết `priceIn`: DS V4.1 Flash 1017 niêm yết $0.15 vs list $0.30). Estimate dùng đúng basis vendor công bố: 10K input (8K cache) + 1K output ⇒ `TOKEN_HARBOR_REQUEST_SHAPE = {inputTokens: 2000, outputTokens: 1000, cacheReadTokens: 8000}` (2K tính giá input, 8K giá cache — KHÔNG phải 10K input đủ), khác profile chung 800 in/50K cache của CC/OC/OD; per_5h = null vì pass không có cửa sổ 5 giờ.
- **Giá trị per-model của pool plan = USAGE VALUE, không phải pool** (chốt 2026-11-09): `plan_models.monthly_credits_usd` với `funding: 'pool'` nghĩa là "pool fund được bao nhiêu usage trên model đó" — OpenDesign lấy **đúng ô `Monthly usage` vendor công bố** ($60 model 1×, $120 model 0.5×, $220 Eco, $30 model 2×, $15 Luna 4×); Token Harbor = `pool × Model Boost` ($10 → $20 GLM). **KHÔNG tự derive `pool ÷ multiplier`** nữa (Eco từng ra $814.81 — số vendor không in ở đâu); công thức đó chỉ còn fallback khi vendor không công bố. Pool thật (**$60 OD**, $10–$35 TH) chỉ nằm ở plan card + note row. Chart đổi tiêu đề "Monthly value per model" / "Requests per month vs monthly value", tooltip pool plan ghi `$X usage`.
- **OpenDesign: requests lấy từ bảng "Coding Plan usage" của vendor (PR #54)** — cột `Est. requests / 7 days`, tab **Go** (rows là `div.dpu-row`, không phải `<tr>`; ô số 1 = requests, ô 2 = usage chuẩn hoá). `per_week` = số công bố, `per_month` = ×4 (chu kỳ 4 cửa sổ 7 ngày: weekly cap = 25% monthly), `per_5h` = ×(8.2% của tháng, tức 4.91/60). Model không có giá per-token (MiniMax M3.1, Eco) **vẫn có request** nhờ bảng này. `monthly_credits_usd` = **ô `Monthly usage` vendor công bố**; chỉ khi vendor không in thì mới fallback `pool ÷ multiplier` — cột này chính là `baseline ÷ multiplier`, nên nó cũng là căn cứ để suy ra pool $60 (xem `designCreditBaseline`). Dòng promo off-peak (usage ghi `/ week`) bị loại.
